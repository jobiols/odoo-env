# Proposal: qa-coverage-ci

**Status**: draft
**Date**: 2026-06-14

---

## Intent

Extract the "run the tests of all Odoo modules in a repository, with coverage" logic
into a reusable Python library inside `odoo-env`, and ship a CI/CD template so client
repositories (e.g. dimec 17.0e) can gate Pull Requests on test results and coverage,
running on a **self-hosted GitHub Actions runner**.

Today:

- `oe -Q` runs a single `docker run` with `--test-enable -u <modules>` and only checks
  the process exit code. Odoo can return **exit 0 even when a test fails**, so this gate
  is unreliable.
- Coverage exists only as a standalone, hardcoded reference script
  (`run_tests.py` in a client repo) that is not integrated anywhere.
- There is no per-PR enforcement, no coverage threshold, and no coverage badge.

This change turns that reference logic into a first-class, parametrized engine owned by
`oe`, plus a CI template that any client repo can drop in.

---

## Goals

1. A reusable library `odoo_env/qa/` that can:
   - discover all module tests in a repository,
   - run every module's tests with coverage (`coverage run -p`),
   - reliably detect failures (exit code **and** `: FAIL: / : ERROR:` output parsing),
   - combine coverage and produce text/xml/json/html reports,
   - enforce a global coverage threshold.
2. A thin CLI (`python -m odoo_env.qa`) invokable both by `oe` and directly by GitHub Actions.
3. A GitHub Actions workflow **template** for client repos that, on a self-hosted runner:
   - provisions a test database (thin seed: `base` + demo, generated by Odoo and cached),
   - runs the engine over all modules,
   - **fails the PR** when coverage `< N` or any test fails,
   - on push to `master`, regenerates a committed coverage **badge** (`coverage.svg`).
4. A coverage threshold that is **easily adjustable in the repo** and behaves as a
   **ratchet**: it can be raised but never silently lowered.

---

## Non-Goals

- A coverage gate for `odoo-env`'s **own** unittest suite (pure Python, no Docker). Out of scope.
- Replacing `oe -Q` selective-module testing. `-Q` stays; the new engine is the "all modules + coverage" path.
- Publishing `odoo_env/qa` as a separate pip package. It ships inside `odoo-env`.
- Managing the self-hosted runner infrastructure (Docker, postgres image, network) — assumed present.
- Supporting Odoo ≥19 demo-data semantics in the first slice (target is 17.0e; design must not block it).

## Approach (high level — details go to design.md)

### The seam: `RunnerConfig`

```python
@dataclass
class RunnerConfig:
    client: str
    version: str          # e.g. "17.0e"
    base_dir: str
    image: str            # from the oe manifest
    db_name: str          # "<client>_test"
    network: str = "odoo-net"
    omit: list[str] = ...  # */tests/*, */__manifest__.py, ...
    coverage: bool = True
    with_demo: bool | None = None   # None => version default (<=18 on)
```

`oe` builds it from `Client`/`OeConfig`; the CI CLI builds it the same way (auto-detect
from the oe manifest in the checked-out client repo). The runner stays environment-agnostic.

### Reliable failure detection (the key reliability fix)

The engine parses each module's streamed output for `:\s+(FAIL|ERROR): \w` (ported from
`run_tests.py`) **and** checks the exit code. Either one fails the run. This is what makes
the PR gate trustworthy despite Odoo's exit-0-on-failure behaviour.

### Thin-seed test DB with cache

```
actions/cache (key = odoo image tag)
  miss: odoo -d <client>_test -i base [--with-demo if >=19] --stop-after-init  -> dump -> cache save
  hit:  restore seed dump
loop per module: coverage run -p ... odoo -i <module> --test-enable  (writes to mounted data_dir)
combine -> report --fail-under=N -> xml/json -> (master) genbadge coverage.svg
```

A fresh Odoo DB provides demo data (≤18 default) and `admin/admin`, so **no committed
`test.zip` is required**.

### Coverage ratchet

The threshold lives in a versioned file in the client repo, easily edited. CI enforces
`coverage report --fail-under=<floor>`. A guard rejects a PR that **lowers** the stored
floor; optionally, on `master`, the floor auto-raises when measured coverage exceeds it.

### Badge

`genbadge` (actively maintained; `coverage-badge` is in maintenance) turns `coverage.xml`
into `coverage.svg`, committed on `master` only. README references the local SVG — fully
self-contained, no external gist/service.

## Risks & Open Questions

| Risk | Mitigation |
|------|-----------|
| First CI run installs all modules (slow) | Inherent to "all modules"; cache keeps the seed warm |
| Postgres provisioning on the runner | Design.md must specify how `pg-<client>` is brought up |
| Coverage data perms under `--rm` | Write to mounted `data_dir` (uid 1100 writable), as in `run_tests.py` |
| Odoo ≥19 demo flip | `RunnerConfig.with_demo` parametrizes it; default keeps 17.0e behaviour |
| Ratchet auto-raise could be surprising | Make auto-raise opt-in; manual floor edits always allowed upward |

---

## Acceptance (definition of done for the change)

- `odoo_env/qa/` engine + CLI exist, unit-tested under strict TDD.
- Engine fails on test failure (exit code OR FAIL/ERROR line) and on coverage `< floor`.
- CI template exists and is documented; validated end-to-end on **dimec 17.0e**.
- Threshold is repo-adjustable and cannot be silently lowered.
- Coverage badge renders in the client README from a committed `coverage.svg`.
